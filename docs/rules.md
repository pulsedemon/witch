# Witch rules

## Goal and constraints

Build a full-screen terminal app for the installed Codex and Claude Code. This is a personal macOS app with production-quality, maintainable code.

Use TypeScript, pnpm, React and Ink in one package. Use strict types, direct imports and behavioral tests. No direct provider runner, remote service, parallel task execution within a conversation, automatic Git pushes, imported conversations or changes to separately launched agents. Separate instances run concurrently, each with one conversation open.

## Ownership

- UI renders coordinator state and submits typed actions. It owns focus, scrolling and hyperlink rendering, not processes or Git. The status line's Git and pull request fields come from `RepositoryWatch` in [repository.ts](../src/core/repository.ts). `/jobs` lists and stops the process groups the agents' commands and Claude `!` commands start, including what a command leaves under launchd once its shell exits. `JobWatch` in [jobs.ts](../src/core/jobs.ts) tracks and signals them; [the CLI](../src/cli.tsx) carries its ownership checkpoint across `/restart`. Tmux processes, their observed descendants and any group containing them are excluded; a Witch inside tmux still manages its own agent commands. A marked launchd child running an app's main executable in a group of its own, as LaunchServices starts the VS Code that `code` opens, or a helper from an app's Frameworks directory, such as its crash handler, is excluded the same way. The composer's ↑/↓ prompt history reads and appends through `StateStore` in [store.ts](../src/persistence/store.ts).
- What follows a merge belongs to `watchMerges`, `cleanUpMerge` and `refreshInstall` in [merged.ts](../src/core/merged.ts) and `cleanUpMerge` in [coordinator.ts](../src/core/coordinator.ts), which say when and what goes. Moving a checkout never overwrites an uncommitted change or an ignored file. [instanceDirectory](../src/persistence/instance.ts) owns each instance's job-report directory; [ScratchSpace](../src/persistence/scratch.ts) owns the agents' `TMPDIR`, its lifetime and cleanup. [Scratch usage observation](../src/persistence/scratch-usage.ts) owns the process and file evidence for cleanup.
- Coordinator owns logical conversations, native session mappings, turn lifecycle and durable handoffs.
- `SessionCoordination` in [coordination.ts](../src/core/coordination.ts) owns live session discovery, task admission and context. [The coordination store](../src/persistence/coordination.ts) owns claim transactions, and [the control transport](../src/persistence/control.ts) carries commands from native agents.
- Adapters own native protocols, processes, permission requests and capabilities.
- Memory owns scoped files, accepted revisions, Git commits, publishing and interrupted-write recovery.
- Persistence owns atomic metadata, append-only display history, each directory's prompt history and conversation locks. [Directory recovery](../src/persistence/directory-recovery.ts) owns explicit checkout moves and retained backups; [startup recovery](../src/core/startup-recovery.ts) reconciles abandoned conversations. [The CLI](../src/cli.tsx) holds the state-directory lock while a normal session runs.

Native types stay in adapters. The steps for adding a backend are in the [README](../README.md). Keep facts in their owning source, with documentation linking to it.

## Native adapters and execution

Discover installed executables. Use Codex app-server over stdio and Claude Agent SDK with the installed Claude Code. Tested versions are recorded in the [README](../README.md). Preserve native prompts, instruction loading, skills, settings, hooks, integrations and permissions. Forward approvals, questions and MCP elicitation, and post a notice for a Codex MCP server that fails to start. Keep credentials native.

Use ordinary input for changing memory and handoffs. Do not overwrite Codex instruction configuration or rely on changed Claude system-prompt snapshots. [nativePrompt](../src/core/prompts.ts) owns instruction precedence and conflict-warning guidance. It keeps the exact user request separate from Witch context so native authorization can retain it independently. [ModelCatalog](../src/core/models.ts) combines native discovery without connecting another conversation; [Coordinator.selectModel](../src/core/coordinator.ts) owns selection and handoff. Accept explicit model IDs without silently substituting models. Reflect actual model and permission settings. Discover skills with Codex skills/list and Claude supportedCommands, and replace the list on Codex skills/changed and Claude commands_changed. Claude's built-ins, apart from clear, effort and fast, are listed as native commands the composer doesn't offer; those three go to Claude as text because they change history or settings Witch tracks. Run a skill natively: Codex gets a skill input with its path, Claude gets `/name args` as the last text block after Witch's context. Connect the agent when a conversation opens, so its skills are listed before the first prompt. Witch's UI and its instructions to the agent call skills spells, subagents familiars and background commands brews. A tool row under Witch's name shows the native name when expanded.

A `!` command runs natively where it can. Codex runs it through `thread/shellCommand`, which records it in the thread. Claude Code's SDK has no such request, so Witch runs it in the user's shell, and the record goes ahead of the next prompt, modeled on Claude Code's own `!`. Either way, the prompt then goes as a turn of its own, or into a turn held open after its reply as below, and says the command already ran.

A prompt sent during a turn steers that turn: Claude Code folds it in at its next tool step through its own input queue, and Codex takes it through turn/steer. After its reply, [ClaudeSession](../src/agents/claude.ts) owns ordinary input admission and completion through native consumption acknowledgements and idle. While a background familiar or workflow holds the turn open, Witch takes a model change, which otherwise needs idle. That model change finishes before the next queued turn; interruption cancels one still in progress. Witch runs a `!` command sent then at once and steers its reply in once it completes. Until then the turn stays open and takes no other prompt or model change. Witch runs its own commands itself. Any other prompt that starts with `/` is a command only when its first word names a listed spell or native command; any other, such as a path, steers as a prompt, and Claude gets it as written. A spell or native command sent during a turn goes to the runtime once it can take it: Claude runs it after the current native turn within the same turn, and without message lifecycle only once the turn has replied. One the runtime refuses, as Codex does since it runs a spell only at a turn's start, waits in Witch's queue for a turn of its own without holding the prompts sent after it. Any other prompt the turn can't take waits in Witch's queue for a later turn: one the turn refuses, one sent behind a queued ordinary prompt or `!` command, one sent after an interrupt, or a `!` command outside the supported window. Queued, a spell, native command or `!` command goes alone, and the prompts before the next one go as one turn, a line each. Once a queued turn's prompt is sent, the prompts queued behind it steer into that turn; the prompts queued behind a `!` command wait for a turn after it. Witch's other commands that act on the conversation, such as /new and cross-runtime /model selection, still need idle. In that window, outside a `!` command, their refusal says to wait for the running familiars or workflows, or press Escape. A switch to another conversation is refused while prompts are queued and takes none until the next one opens. An interrupt leaves the queue to run next, along with the prompts Claude Code reports it never read. Unread records of completed Claude `!` commands stay with their conversation until its next dispatched prompt, even across a native reconnect or conversation switch. They go as context without queuing another turn or rerunning the commands, and remain only for the current Witch process. A queued turn that never reaches the agent keeps its prompts queued, a report or a failed turn keeps the rest queued so it stays on screen, and the composer takes them back.

Claude result alone does not establish idle; completion must follow native lifecycle.

Native compaction scheduling, queue preservation and memory invalidation belong to `Coordinator.compact`, `drain` and `receive` in [coordinator.ts](../src/core/coordinator.ts). [nativePrompt](../src/core/prompts.ts) supplies accepted memory after confirmed history replacement. Native sessions, settings, hooks and Witch's transcript persist across compaction.

Codex commands that outlive their originating native turn become brews through [CodexSession](../src/agents/codex.ts); later turns leave them visible until completion. [Coordinator](../src/core/coordinator.ts) keeps unfinished tool output on its original transcript row throughout that native connection.

Codex and Claude can delegate work to each other when the other runtime suits the user's task. This is general-purpose delegation, including implementation, investigation and review. [The Claude wrapper](../src/cli-familiar.ts) and [Codex wrapper](../src/cli-codex-familiar.ts) use the bound invocations supplied by [nativePrompt](../src/core/prompts.ts). Native commands retain execution, permission and job ownership. [CodexCommands](../src/agents/codex-commands.ts) and [ClaudeCommands](../src/agents/claude-commands.ts) own task association and lifecycle. [ClaudeTask](../src/agents/claude-task.ts) translates Claude's stream; the Codex wrapper reuses [CodexAdapter](../src/agents/codex.ts) and forwards its native requests through Witch. A native result alone does not establish process cleanup. The wrappers save complete reports to new task-scratch files. This reporting path does not survive `/restart`.

## Terminal UI and persistence

Task titles, attention eligibility and pending-alert cancellation belong to [watchTerminal](../src/ui/terminal.ts), which observes coordinator and session-coordination state. [NotificationSchedule](../src/persistence/notifications.ts) owns desktop spacing and its persisted record. [Coordinator](../src/core/coordinator.ts) supplies successful turn completion; [the CLI](../src/cli.tsx) provides the schedule, cancels attention before teardown and resets the title during final terminal restoration.

Use an alternate screen with a phase row at the top, a scrolling transcript, a multiline composer that grows with its text up to half the rows the phase row, errors and status line leave, and a two-row status line at the foot, rendered by [StatusLine](../src/ui/status-line.tsx) for either agent, with `~/.claude/statusline.sh` as its baseline. While the agent works, a row above the composer says so and counts the time since it began, and queued prompts show above that row. Each adapter reports what its agent can of context, limits and changed lines, and an unreported field takes the script's default. A right sidebar beside a main column of at least 80 cells shows peer sessions, then the live session's running brews by what they're for, then its running familiars, each nested under the familiar that started it while that one runs, with its time, tool count and latest tool call, above a pentacle controlled through [PentacleActivity](../src/core/pentacle-activity.ts), with default activity supplied by [Coordinator](../src/core/coordinator.ts). Brews take rows first, after a running familiar's heading and count. Sessions/models use pickers; memory has a list and preview. Keys and commands are defined by the `/help` text in [app.tsx](../src/ui/app.tsx).

Follow output only at the bottom. Keep typing responsive with long expanded tool results and while an image loads or converts, preserve scroll on view changes and resize, batch streamed display changes and reuse completed rendering. Capture the mouse: the wheel scrolls, the pointer turns into a hand over a link and a click opens it, and a drag selects transcript text, drawn as the terminal draws a selection, for Cmd+C to copy with wrapped rows joined. A drag past the transcript's top or bottom scrolls it. Shift+drag keeps native selection, and mouse reporting ends on exit. Web links use OSC 8 and the default browser. File references use encoded VS Code URLs with optional line/column, resolved against their originating cwd. A click opens a file only if it exists and otherwise posts an unsaved notice. A name with no directory that its cwd lacks opens the conversation's shared-memory note of that name, and the notice lists both when both scopes have one. Underline every link, and preserve links and their underline in Markdown, bare text, tool output, wrapping, clipping and selection. A message shows the images it names and an expanded tool the images it returned, drawn as Kitty Unicode placeholders so they scroll and clip as text. A tool that changed files shows each one's diff when expanded, with line numbers and added and removed rows on green and red, and starts expanded when it changed a file under its directory. A diff's code is colored by language apart from removed rows, the words a changed row changed show brighter, and an added or removed row's number and marker turn green or red. A copied diff keeps each row on its own line. An answered question stays in the transcript with its answers. Each familiar's and brew's start and end add transcript rows, a familiar's end with its report. A Codex familiar's notices post to the transcript under its name.

Observed familiar identity belongs to [CodexSession](../src/agents/codex.ts), [ClaudeSession](../src/agents/claude.ts) and [ClaudeTask](../src/agents/claude-task.ts). [Sidebar](../src/ui/sidebar.tsx) wraps identity within complete entries; [familiar projection](../src/core/familiars.ts) preserves their transcript rows when identity arrives or changes.

Approval previews come from the adapters; [Request](../src/ui/request.tsx), [TranscriptLayout](../src/ui/transcript-layout.ts) and [the diff renderer](../src/ui/diff.ts) own their display and full-file expansion.

Persist native IDs and display history. Each instance has one conversation open, and its coordinator exclusively owns that state. Refuse a conversation another instance holds; recover after a dead owner, stopping the agent and the shell of a Claude `!` command it left running, and reconcile native execution. Never automatically replay a prompt.

## Session coordination

GitHub assignment after an active claim belongs to [assignGitHubTask](../src/core/github-assignment.ts); [SessionCoordination](../src/core/coordination.ts) retains the local claim and returns a warning when assignment fails. The claim records each reference GitHub confirmed, and a later `--claim` assigns only its other references.

Witches sharing a state directory discover this repository's other open sessions, including its other checkouts. `/peers` shows their tasks and details without switching or messaging them. The sidebar reserves space for local brews and familiars before allocating peer rows; [Sidebar](../src/ui/sidebar.tsx) owns that budget.

Observed merge delivery is owned by [SessionCoordination](../src/core/coordination.ts), the [coordination store](../src/persistence/coordination.ts), and the [event contract and projections](../src/core/merge-events.ts). [nativePrompt](../src/core/prompts.ts) supplies attributed events on eligible turns; [session state](../src/core/state.ts) owns their delivery receipts.

Agents receive fixed Witch instructions, including bound control and familiar commands, on their first native turn, after confirmed compaction and when the instruction text changes. Successful delivery is recorded per native session. Each dispatched turn still receives a fresh peer snapshot and the current selection turn ID, or an explicit indication that no selection turn is current. They query and claim a full GitHub issue/pr URL or `task:name` before starting work. Matching references and explicit aliases have one owner; differently named descriptions of the same work still require the agent to recognize the overlap. Every claim lasts only while its Witch conversation stays open. Switching conversations, normal exit and process death release it; idle time, native reconnect and restart preserve it. `/task` shows this conversation's claim or selection position; `/task release` requires idle, resolved memory recovery and no running familiars or brews. An origin change leaves its existing reservation in the original project until release.

When choosing the next task, agents wait in a project queue before triage. Reserving a recommendation advances the next chooser immediately. Suggestions stay reserved until the user requests work, chooses another task or leaves the conversation; they survive native reconnect and restart. Requested work promotes a suggestion to an active claim. Turn completion or interruption cancels unfinished selection, and failed cancellation retries automatically. [SessionCoordination](../src/core/coordination.ts) owns turn authority and cleanup; [CoordinationStore](../src/persistence/coordination.ts) owns FIFO order and atomic reservation transitions.

A conversation held by a current Witch does not count as unregistered, including while it opens, reconnects or closes; [StateStore](../src/persistence/store.ts) owns the locks that distinguish current and legacy owners. Restart or close older instances that appear unregistered before claiming new work. Selection also requires every live peer to support the queue. Discovery failures refuse new claims. A failed or timed-out control call grants no permission to begin work; query again to determine the outcome. The command uses files under the running instance's scratch directory and preserves native sandbox permissions. The task mailbox controls ownership; a separate familiar mailbox reports only registered native commands in the active conversation. Neither controls another session's execution or files.

## Shared memory

Keep memory in a dedicated bare Git repository, separate from logs and handoff state, and give each conversation its own worktree on its own branch. Separate global and project scopes. A project is the repository Git reaches through the origin remote, so clones share one across URL and scp forms, user names and host case. Path case still matters, and an SSH host alias counts as a host of its own. A local origin that is a repository with an origin of its own names that origin's project. A checkout without an origin, or a directory outside any repository, is a project of its own. `Workspace.begin` and `Workspace.adoptCheckout` in [workspace.ts](../src/memory/workspace.ts) own checkout-note migration and its startup recovery gates. Existing project docs remain authoritative. Agents use ordinary file tools and scoped native permissions; only the coordinator manages memory Git operations.

Each turn begins with clean memory and durable base-revision and agent metadata. Successful completion commits that turn's changes, with attribution and no empty commits. Accepted memory is `main`; a clean worktree publishes its commits by rebasing onto `main`. Interrupted, failed or uncommitted changes remain pending; block new execution until explicit accept/discard recovery. MEMORY.md, the index every agent keeps, merges both sides' lines. Any other change that conflicts with another conversation's enters conflict recovery, where keep mine resolves each conflicting change to this conversation's side and merges the rest, and discard mine resets to `main`. Never sweep another turn's pending changes into a later commit.

Before every turn, compare the accepted revision and project with those last delivered to the session, and reconnect a session granted another project's memory. Supply current essentials and changes/deletions, explicitly superseding old content. Search deeper notes as files. Memory UI supports search, history, VS Code editing while paused and restoration through a new commit. No vector store.

Snapshot delivery and memory-writing guidance belong to `Memory.snapshot` in [memory.ts](../src/memory/memory.ts) and `nativePrompt` in [prompts.ts](../src/core/prompts.ts).

## Handoffs and recovery

Stop or finish the source and resolve memory; generate and save its handoff; initialize the destination; atomically activate it; submit current context and continuation. Before activation, failure retains the source. After activation, failure leaves the destination resumable. Return-to-agent resumes its prior native session. Keep both sessions and never replay automatically.
