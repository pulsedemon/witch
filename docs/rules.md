# Witch rules

## Goal and constraints

Build a full-screen terminal app for the installed Codex and Claude Code. This is a personal macOS app with production-quality, maintainable code.

Use TypeScript, pnpm, React and Ink in one package. Use strict types, direct imports and behavioral tests. No direct provider runner, remote service, parallel task execution within a conversation, automatic Git pushes, imported conversations or changes to separately launched agents. Separate instances run concurrently, each with one conversation open.

## Ownership

- UI renders coordinator state and submits typed actions. It owns focus, scrolling and hyperlink rendering, not processes or Git. The status line's Git and pull request fields come from `RepositoryWatch` in [repository.ts](../src/core/repository.ts). `/jobs` lists and stops the process groups the agents' commands and Claude `!` commands start, including what a command leaves under launchd once its shell exits. `JobWatch` in [jobs.ts](../src/core/jobs.ts) tracks and signals them. The composer's ↑/↓ prompt history reads and appends through `StateStore` in [store.ts](../src/persistence/store.ts).
- What follows a merge belongs to `watchMerges`, `cleanUpMerge` and `refreshInstall` in [merged.ts](../src/core/merged.ts) and `cleanUpMerge` in [coordinator.ts](../src/core/coordinator.ts), which say when and what goes. Moving a checkout never overwrites an uncommitted change or an ignored file. Each instance owns `jobs/<pid>` and `scratch/<pid>` in the state directory, removed when it exits or at a later launch. `scratch/<pid>` is the agents' `TMPDIR`.
- Coordinator owns logical conversations, native session mappings, turn lifecycle and durable handoffs.
- Adapters own native protocols, processes, permission requests and capabilities.
- Memory owns scoped files, accepted revisions, Git commits, publishing and interrupted-write recovery.
- Persistence owns atomic metadata, append-only display history, each directory's prompt history and conversation locks.

Native types stay in adapters. The steps for adding a backend are in the [README](../README.md). Keep facts in their owning source, with documentation linking to it.

## Native adapters and execution

Discover installed executables. Use Codex app-server over stdio and Claude Agent SDK with the installed Claude Code. Tested versions are recorded in the [README](../README.md). Preserve native prompts, instructions, skills, settings, hooks, integrations and permissions. Forward approvals, questions and MCP elicitation. Keep credentials native.

Use ordinary input for changing memory and handoffs. Do not overwrite Codex instruction configuration or rely on changed Claude system-prompt snapshots. Discover models with paginated Codex model/list and Claude supportedModels; idle Claude refresh uses reinitialize. Accept explicit model IDs without silently substituting models. Reflect actual model and permission settings. Discover skills with Codex skills/list and Claude supportedCommands without its built-ins, and replace the list on Codex skills/changed and Claude commands_changed. Run a skill natively: Codex gets a skill input with its path, Claude gets `/name args` as the last text block after Witch's context. Connect the agent when a conversation opens, so its skills are listed before the first prompt. Witch's UI calls skills spells, subagents familiars and background commands brews.

A `!` command runs natively where it can. Codex runs it through `thread/shellCommand`, which records it in the thread. Claude Code's SDK has no such request, so Witch runs it in the user's shell, and the record goes ahead of the next prompt, modeled on Claude Code's own `!`. Either way, the prompt then goes as a turn of its own, or into a turn held open after its reply as below, and says the command already ran.

A prompt sent during a turn steers that turn: Claude Code folds it in at its next tool step through its own input queue, and Codex takes it through turn/steer. After its reply, Claude Code keeps the turn open until every background familiar and workflow reports, and it answers a prompt steered meanwhile without waiting for them. In that window it also runs a spell as a turn of its own, and Witch takes a model change, which otherwise needs idle. Witch runs a `!` command sent then at once and steers its reply in once it completes. Until then the turn stays open and takes no other prompt or model change. Any other prompt the turn can't take waits in Witch's queue until nothing else runs, then goes as a turn: one sent behind queued ones, after an interrupt or after the reply while no familiar or workflow runs, and any other slash command or `!` command. Steered raw, Claude Code would run a slash command as its own, so one the window doesn't take waits. Queued, a slash command or `!` command goes alone, and the prompts before the next one go as one turn, a line each. Witch's other commands that act on the conversation, such as /new and /agent, still need idle. In that window, outside a `!` command, their refusal says to wait for the running familiars or workflows, or press Escape. A switch to another conversation is refused while prompts are queued and takes none until the next one opens. An interrupt leaves the queue to run next, along with the prompts Claude Code reports it never read, apart from a `!` command's reply, whose command already ran. A queued turn that never reaches the agent keeps its prompts queued, a report or a failed turn keeps the rest queued so it stays on screen, and the composer takes them back.

Claude result alone does not establish idle; completion must follow native lifecycle.

## Terminal UI and persistence

Use an alternate screen with a phase row at the top, a scrolling transcript, a multiline composer that grows with its text up to half the rows the phase row, errors and status line leave, and a two-row status line at the foot showing, for either agent, the fields `~/.claude/statusline.sh` shows, rendered by Witch without running the script. While the agent works, a row above the composer says so and counts the time since it began, and queued prompts show above that row. Each adapter reports what its agent can of context, cost, limits and changed lines, and an unreported field takes the script's default. A right sidebar beside a main column of at least 80 cells lists the live session's running brews by what they're for, then its running familiars, each nested under the familiar that started it while that one runs, with its time, tool count and latest tool call, above a pentacle that turns while the agent works. Brews take rows first, after a running familiar's heading and count. Sessions/models use pickers; memory has a list and preview. Keys and commands are defined by the `/help` text in [app.tsx](../src/ui/app.tsx).

Follow output only at the bottom. Keep typing responsive with long expanded tool results, preserve scroll on view changes and resize, batch streamed display changes and reuse completed rendering. Capture the mouse: the wheel scrolls, the pointer turns into a hand over a link and a click opens it, and a drag selects transcript text, drawn as the terminal draws a selection, for Cmd+C to copy with wrapped rows joined. A drag past the transcript's top or bottom scrolls it. Shift+drag keeps native selection, and mouse reporting ends on exit. Web links use OSC 8 and the default browser. File references use encoded VS Code URLs with optional line/column, resolved against their originating cwd. Underline every link, and preserve links and their underline in Markdown, bare text, tool output, wrapping, clipping and selection. A message shows the images it names and an expanded tool the images it returned, drawn as Kitty Unicode placeholders so they scroll and clip as text. A tool that changed files shows each one's diff when expanded, with line numbers and added and removed rows on green and red, and starts expanded when it changed a file under its directory. A diff's code is colored by language apart from removed rows, the words a changed row changed show brighter, and an added or removed row's number and marker turn green or red. A new or deleted file shows its first 10 lines, and a copied diff keeps each row on its own line. An answered question stays in the transcript with its answers. Each familiar's and brew's start and end add transcript rows, a familiar's end with its report.

Persist native IDs and display history. Each instance has one conversation open, and its coordinator exclusively owns that state. Refuse a conversation another instance holds; recover after a dead owner, stopping the agent and the shell of a Claude `!` command it left running, and reconcile native execution. Never automatically replay a prompt.

## Shared memory

Keep memory in a dedicated bare Git repository, separate from logs and handoff state, and give each conversation its own worktree on its own branch. Separate global and project scopes. A project is the repository Git reaches through the origin remote, so clones share one across URL and scp forms, user names and host case. Path case still matters, and an SSH host alias counts as a host of its own. A local origin that is a repository with an origin of its own names that origin's project. A checkout without an origin, or a directory outside any repository, is a project of its own. When Witch opens and before each turn, the notes keyed by a checkout's path merge into its origin's project: MEMORY.md gains the lines it lacks, and a note both hold keeps both versions. Existing project docs remain authoritative. Agents use ordinary file tools and scoped native permissions; only the coordinator manages memory Git operations.

Each turn begins with clean memory and durable base-revision and agent metadata. Successful completion commits that turn's changes, with attribution and no empty commits. Accepted memory is `main`; a clean worktree publishes its commits by rebasing onto `main`. Interrupted, failed or uncommitted changes remain pending; block new execution until explicit accept/discard recovery. MEMORY.md, the index every agent keeps, merges both sides' lines. Any other change that conflicts with another conversation's enters conflict recovery, where keep mine resolves each conflicting change to this conversation's side and merges the rest, and discard mine resets to `main`. Never sweep another turn's pending changes into a later commit.

Before every turn, compare the accepted revision and project with those last delivered to the session, and reconnect a session granted another project's memory. Supply current essentials and changes/deletions, explicitly superseding old content. Search deeper notes as files. Memory UI supports search, history, VS Code editing while paused and restoration through a new commit. No vector store.

## Handoffs and recovery

Stop or finish the source and resolve memory; generate and save its handoff; initialize the destination; atomically activate it; submit current context and continuation. Before activation, failure retains the source. After activation, failure leaves the destination resumable. Return-to-agent resumes its prior native session. Keep both sessions and never replay automatically.
