# Witch rules

## Goal and constraints

Build a full-screen terminal app for the installed Codex and Claude Code. This is a personal macOS app with production-quality, maintainable code.

Use TypeScript, pnpm, React and Ink in one package. Use strict types, direct imports and behavioral tests. No direct provider runner, remote service, parallel task execution within a conversation, automatic Git pushes, imported conversations or changes to separately launched agents. Separate instances run concurrently, each with one conversation open.

## Ownership

- UI renders coordinator state and submits typed actions. It owns focus, scrolling and hyperlink rendering, not processes or Git. The status line's Git and pull request fields come from `RepositoryWatch` in [repository.ts](../src/core/repository.ts). `/jobs` lists and stops the process groups the agents' commands and Claude `!` commands start, including what a command leaves under launchd once its shell exits. `JobWatch` in [jobs.ts](../src/core/jobs.ts) tracks and signals them; [the CLI](../src/cli.tsx) carries its ownership checkpoint across `/restart`. Tmux processes, their observed descendants and any group containing them are excluded; a Witch inside tmux still manages its own agent commands. A marked launchd child running an executable in an app's `Contents/MacOS` in a group of its own, as LaunchServices starts the VS Code that `code` opens, or a helper from its `Contents/Frameworks`, such as its crash handler, is excluded the same way. Only the outermost app outside a framework matches. The composer's ↑/↓ prompt history reads and appends through `StateStore` in [store.ts](../src/persistence/store.ts).
- Cleanup after the branch's own pull request merges belongs to `watchMerges`, `cleanUpMerge` and `refreshInstall` in [merged.ts](../src/core/merged.ts) and `cleanUpMerge` in [coordinator.ts](../src/core/coordinator.ts), which say when and what goes. Moving a checkout never overwrites an uncommitted change or an ignored file. [instanceDirectory](../src/persistence/instance.ts) owns each instance's job-report directory; [ScratchSpace](../src/persistence/scratch.ts) owns the agents' `TMPDIR`, its lifetime and cleanup. [Scratch usage observation](../src/persistence/scratch-usage.ts) owns the process and file evidence for cleanup.
- Coordinator owns logical conversations, native session mappings, turn lifecycle and durable handoffs.
- `SessionCoordination` in [coordination.ts](../src/core/coordination.ts) owns live session discovery, task admission and context. [The coordination store](../src/persistence/coordination.ts) owns claim and peer-request transactions, and [the control transport](../src/persistence/control.ts) carries commands from native agents.
- Adapters own native protocols, processes, permission requests and capabilities.
- Memory owns scoped files, accepted revisions, Git commits, publishing and interrupted-write recovery.
- Persistence owns atomic metadata, append-only display history, each directory's prompt history and conversation locks. [Directory recovery](../src/persistence/directory-recovery.ts) owns explicit checkout moves and retained backups; [startup recovery](../src/core/startup-recovery.ts) reconciles abandoned conversations. [The CLI](../src/cli.tsx) holds the state-directory lock while a normal session runs.

Native types stay in adapters. The steps for adding a backend are in the [README](../README.md). Keep facts in their owning source, with documentation linking to it.

## Native adapters and execution

Discover installed executables. Use Codex app-server over stdio and Claude Agent SDK with the installed Claude Code. Tested versions are recorded in the [README](../README.md). Preserve native prompts, instruction loading, skills, settings, hooks, integrations and permissions. Forward approvals, questions and MCP elicitation. Post transient notices for a Codex MCP server that fails to start and a Claude MCP server that fails to connect or needs sign-in. [ClaudeSession](../src/agents/claude.ts) owns Claude notice timing and deduplication. Keep credentials native.

Use ordinary input for changing memory and handoffs. Do not overwrite Codex instruction configuration or rely on changed Claude system-prompt snapshots. [nativePrompt](../src/core/prompts.ts) owns instruction precedence, conflict-warning guidance and the layout of transcript replies. It also owns automatic follow-up auditing and issue filing after an agent opens a pull request. It keeps the exact user request separate from Witch context so native authorization can retain it independently. Answer turns have no user request: their context lists peer requests by id, and `Coordinator.performTurn` sends a fixed Witch instruction with `author: 'witch'`. [ModelCatalog](../src/core/models.ts) combines native discovery without connecting another conversation; [Coordinator.selectModel](../src/core/coordinator.ts) owns selection and handoff. Accept explicit model IDs without silently substituting models. Reflect actual model and permission settings. Discover skills with Codex skills/list and Claude supportedCommands, and replace the list on Codex skills/changed and Claude commands_changed. Claude's built-ins are listed as native commands the composer doesn't offer, except the commands sent as text under [Claude command routing](#claude-command-routing). Run a skill natively: Codex gets a skill input with its path, Claude gets `/name args` as the last text block after Witch's context. Witch announces each spell cast in the transcript with a brief animation: one the user sends, once the runtime takes it, and one the agent or a familiar casts through Claude's Skill tool or, on Codex, by reading a listed spell's SKILL. Connect the agent when a conversation opens, so its skills are listed before the first prompt. Witch's UI and its instructions to the agent call skills spells, subagents familiars and background commands brews. A tool row under Witch's name shows the native name when expanded.

A `!` command runs natively where it can. Codex runs it through `thread/shellCommand`, which records it in the thread. Claude Code's SDK has no such request, so Witch runs it in the user's shell, and the record goes ahead of the next prompt, modeled on Claude Code's own `!`. Either way, the prompt then goes as a turn of its own, or into a turn held open after its reply as below, and says the command already ran.

A prompt sent during a turn steers that turn: Claude Code folds it in at its next tool step through its own input queue, and Codex takes it through turn/steer. After its reply, [ClaudeSession](../src/agents/claude.ts) owns ordinary input admission and completion through native consumption acknowledgements and idle. While a background familiar or workflow holds the turn open, Witch takes a model change, which otherwise needs idle. That model change finishes before the next queued turn; interruption cancels one still in progress. Witch runs a `!` command sent then at once and steers its reply in once it completes. Until then the turn stays open and takes no other prompt or model change. A model change chosen, or a `/model` picker opened, after the native turn ends, while Witch is still settling that turn, waits for settlement and then applies or opens. If Witch is interrupted, or the turn or its settlement fails, it lapses with a notice. Witch runs its own commands itself. Any other prompt that starts with `/` is a command only when its first word names a listed spell or native command; any other, such as a path, steers as a prompt, and Claude gets it as written. A spell or native command sent during a turn goes to the runtime once it can take it: Claude runs it after the current native turn within the same turn, and without message lifecycle only once the turn has replied. One the runtime refuses, as Codex does since it runs a spell only at a turn's start, waits in Witch's queue for a turn of its own without holding the prompts sent after it. Any other prompt the turn can't take waits in Witch's queue for a later turn: one the turn refuses, one sent behind a queued ordinary prompt or `!` command, one sent after an interrupt, or a `!` command outside the supported window. Queued, a spell, native command or `!` command never joins other prompts' text: at the queue's head it goes alone, and the prompts before the next one go as one turn, a line each. With no session connected, any prompt that starts with `/` goes alone. Once a queued turn's prompt is sent, the prompts queued behind it steer into that turn; the prompts queued behind a `!` command wait for a turn after it. Witch's other commands that act on the conversation, such as /new and cross-runtime /model selection, still need idle. In that window, outside a `!` command, their refusal says to wait for the running familiars or workflows, or press Escape. A switch to another conversation is refused while prompts are queued and takes none until the next one opens. An interrupt leaves the queue to run next, along with the prompts Claude Code reports it never read. Unread records of completed Claude `!` commands stay with their conversation until its next dispatched prompt, even across a native reconnect or conversation switch, unless `/clear` discards them. They go as context without queuing another turn or rerunning the commands, and remain only for the current Witch process. A queued turn that never reaches the agent keeps its prompts queued, a report or a failed turn keeps the rest queued so it stays on screen, and the composer takes them back. Invalid `/task` arguments, failed `/task release` and `/task take`, Witch commands refused because another operation is running, model and spell discovery failures, failed link resolution, and failed desktop open or clipboard commands post transient notices and leave queued prompts runnable. A prompt sent during a Witch-started answer or Copilot-review turn queues and runs after it, or returns to the composer if that turn fails. Commands that need idle are refused during these turns, and Escape stops them.

Claude completion follows native idle once the connection has reported session state. Without any session-state event, [ClaudeSession](../src/agents/claude.ts) completes on a result after tracked native familiars, workflows, accepted input and held command replies settle, and posts a notice that idle tracking is missing.

Explicit interruption and closure share a deadline through [Coordinator](../src/core/coordinator.ts) and the adapters. [Shutdown](../src/agents/shutdown.ts) owns the budget and targeted process escalation. Codex restart retains its existing teardown policy. Normal turns and background work have no deadline.

`/clear` requires idle and no queued prompts, as `/new` does. [Coordinator.clear](../src/core/coordinator.ts) starts a fresh native session inside the same conversation, retaining its claim, scratch, memory workspace, model and effort. It discards both runtimes' saved context, pending handoff and unread command output, and the old ordinary-turn outcome. The next turn receives shared memory and Witch's instructions again. [Issue #43](https://github.com/pulsedemon/witch/issues/43) owns changes to busy-conversation policy.

### Witch commands and compaction

[The command catalog and parser](../src/ui/commands.ts) own names, aliases and arguments. Witch runs every whitespace-delimited command outside backticks in a submitted message, in order. A leading `!` or listed native command preserves the whole input; a leading Witch command takes precedence over a native name collision. Unknown slash words and paths remain ordinary input. Backticks protect literal command names, including an unclosed span through the end of the message. `/new`, `/model`, `/task` and `/delegation` consume arguments up to the next Witch command. Other commands take none. Surrounding prose is discarded, the original message stays in prompt history, and none of it reaches the agent.

[Command batches](../src/ui/command-batches.ts) await operations, picker selection or dismissal, nested effort choices and native model application. They hold prompt delivery across the entire sequence, including separately submitted batches waiting behind it. Failure, refusal or interruption cancels the remaining commands across all accepted batches; a notice lists exact commands and arguments for explicit retry. Completed commands are omitted. Canceled command text never enters the composer. Escape dismisses a picker successfully; Ctrl+P replaces it as a dismissal. Exit and restart discard the remaining sequence. Other commands retain their existing busy-conversation refusal rules.

`/compact` is accepted during work. Codex waits for the active turn to finish because its native manual compaction interrupts that turn. Claude waits for foreground native execution, then compacts while background familiars or workflows can remain active. [ClaudeCompaction](../src/agents/claude-compaction.ts) requires a matching result and confirmed manual history replacement without finishing the ordinary turn. `Pending: /compact` remains visible until the request completes. Concurrent API callers share a request; repeated explicit commands run separately. A manual request joins automatic compaction already in progress.

[Compaction requests](../src/core/compaction.ts) are scoped to their conversation and operation. [Coordinator](../src/core/coordinator.ts) blocks both direct steering and queued delivery from admission until compaction completes, then retains any command-batch hold. Failure, cancellation, recovery or a conversation change stops the request and leaves later prompts undelivered. A failed busy compaction keeps the parent activity's hook writes pending for recovery even if its ordinary result succeeds; a successful one does not commit while the parent remains active. [Memory settlement](../src/core/memory-settlement.ts) classifies unpublished writes and conflicts after the owning operation ends.

Queued input returns to the composer only after delivery holds clear and only when the existing draft and proposed merged text would not execute Witch commands. Unsafe merges retain both the draft and original queue entries. Automatic recovery retries when the draft becomes empty; Up-arrow or another queue/phase transition can recover a nonempty safe draft. With an unsafe queue-only merge, a new ordinary submission resumes the original message boundaries. Fatal errors retain unconditional recovery for copying from the disabled composer.

Automatic compaction follows [Coordinator's pre-turn policy](../src/core/coordinator.ts), which `runTurn` applies to every turn `drain` starts, including answer turns. Native sessions, settings, hooks and Witch's transcript persist across compaction. Confirmed replacement invalidates delivered context; [nativePrompt](../src/core/prompts.ts) supplies accepted memory and Witch instructions at the next dispatched turn. A prompt steered into the current turn does not mark that context delivered.

Codex commands that outlive their originating native turn become brews through [CodexSession](../src/agents/codex.ts); later turns leave them visible until completion. [Coordinator](../src/core/coordinator.ts) keeps unfinished tool output on its original transcript row throughout that native connection.

Agents delegate work only through Witch's familiar wrappers, on either runtime and from either one, never their own subagent tools, since only the wrapper's model argument guarantees the model that runs. This is general-purpose delegation, including implementation, investigation and review. Before each, the agent asks `--route`; [routing.ts](../src/core/routing.ts) owns the choice of runtime and model from the user's `/delegation` policy, the producer of work under review and each runtime's usage, resolving a family to its newest model and running a versioned model as named. A review with no rule goes to every installed runtime, and the agent launches a familiar on each route. A runtime over the usage level shifts its work to one with room, onto the comparable model when the rule names one. [Router](../src/core/router.ts) answers the request and records each choice and its reason in the transcript. The Claude wrapper passes its own settings so a legacy remap or fallback can't replace that model. [The Claude wrapper](../src/cli-familiar.ts) and [Codex wrapper](../src/cli-codex-familiar.ts) use the bound invocations supplied by [nativePrompt](../src/core/prompts.ts). Native commands retain execution, permission and job ownership. [CodexCommands](../src/agents/codex-commands.ts) and [ClaudeCommands](../src/agents/claude-commands.ts) own task association and lifecycle. [ClaudeTask](../src/agents/claude-task.ts) translates Claude's stream; the Codex wrapper reuses [CodexAdapter](../src/agents/codex.ts) and forwards its native requests through Witch. A native result alone does not establish process cleanup. The wrappers save complete reports to new task-scratch files. This reporting path does not survive `/restart`.

### Claude command routing

[textCommands](../src/agents/claude-spells.ts) owns the commands sent as text because they overlap Witch's history, displayed settings, conversation titles or compaction policy. Unlisted slash prompts go as text on both initial and steered input, even without a context prefix.

The state-changing commands audited against the [tested native version](../README.md#development) use these routes:

| Command           | Route                 | Native effect and ownership                                                                                                                                                                                  |
| ----------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `autocompact`     | Native                | Changes the per-model compaction window in user settings; it cannot turn compaction off. Witch retains its pre-turn scheduling.                                                                              |
| `config`          | Text                  | Can disable native auto-compaction and change model settings outside Witch's selection flow.                                                                                                                 |
| `output-style`    | Native                | Selects a native output style and saves it in project-local Claude settings. Claude owns its prompt styles.                                                                                                  |
| `rename`          | Text                  | Changes Claude's session name without changing Witch's conversation title.                                                                                                                                   |
| `advisor`         | Native when available | Configures a separate native advisor, preserving the main model. Saves the advisor choice in native user settings.                                                                                           |
| `auto-mode-setup` | Native                | Proposes and applies Claude's auto-mode environment and classifier rules. Applying a reviewed proposal requires its exact file hash and writes native user settings, including for project-scoped proposals. |

## Terminal UI and persistence

Task titles, attention eligibility and pending-alert cancellation belong to [watchTerminal](../src/ui/terminal.ts), which observes coordinator and session-coordination state. [NotificationSchedule](../src/persistence/notifications.ts) owns desktop spacing and its persisted record. [Coordinator](../src/core/coordinator.ts) supplies successful completion of normal turns, which an answer turn doesn't delay; [the CLI](../src/cli.tsx) provides the schedule, cancels attention before teardown and resets the title during final terminal restoration.

Use an alternate screen with a phase row at the top, a scrolling transcript, a multiline composer that grows with its text up to half the rows the phase row, errors and status line leave, and a two-row status line at the foot, rendered by [StatusLine](../src/ui/status-line.tsx) for either agent, with `~/.claude/statusline.sh` as its baseline. While the agent works, a row above the composer says so and counts the time since it began, and queued prompts show above that row. Each adapter reports what its agent can of context, limits and changed lines, and an unreported field takes the script's default. Once any runtime has reported usage, every installed runtime's usage shows in a block under the sidebar's pentacle; [usage.ts](../src/core/usage.ts) owns what counts as current, and a window that isn't shows dim with its age. The status line carries usage only when the sidebar or its block doesn't fit, dropping the live runtime's reset times before the row would overflow. A right sidebar beside a main column of at least 80 cells shows peer sessions, then the live session's running brews by what they're for, then its running familiars, each nested under the familiar that started it while that one runs, with its time, tool count and latest tool call, above a pentacle controlled through [PentacleActivity](../src/core/pentacle-activity.ts), with default activity supplied by [Coordinator](../src/core/coordinator.ts). Brews take rows first, after a running familiar's heading and count. Sessions/models use pickers; memory has a list and preview. Keys and commands are defined by the `/help` text in [app.tsx](../src/ui/app.tsx).

Follow output only at the bottom. Keep typing responsive with long expanded tool results and while an image loads or converts, preserve scroll on view changes and resize, batch streamed display changes and reuse completed rendering. Capture the mouse: the wheel scrolls, the pointer turns into a hand over a link and a click opens it, and a drag selects transcript text, drawn as the terminal draws a selection, for Cmd+C to copy with wrapped rows joined. A drag past the transcript's top or bottom scrolls it. Shift+drag keeps native selection, and mouse reporting ends on exit. Web links use OSC 8 and the default browser. File references use encoded VS Code URLs with optional line/column, resolved against their originating cwd. Image files use file URLs and open in the system's default image viewer, as does a click on a drawn image; an image a tool returned as data is written to a temporary file when clicked and removed on exit. A click opens a file only if it exists, and an image link only if the file it resolves to is a regular image file, and otherwise posts an unsaved notice. A name with no directory that its cwd lacks opens the conversation's shared-memory note of that name, and the notice lists both when both scopes have one. Underline every link but a drawn image, and preserve links and their underline in Markdown, bare text, tool output, wrapping, clipping and selection. A message shows the images it names and an expanded tool the images it returned, drawn as Kitty Unicode placeholders so they scroll and clip as text. A tool that changed files shows each one's diff when expanded, with line numbers and added and removed rows on green and red, and starts expanded when it changed a file under its directory. A diff's code is colored by language apart from removed rows, the words a changed row changed show brighter, and an added or removed row's number and marker turn green or red. A copied diff keeps each row on its own line. An answered question stays in the transcript with its answers. Each familiar's and brew's start and end add transcript rows, a familiar's end with its report. A Codex familiar's notices post to the transcript under its name.

While reading earlier output, incoming transcript changes show a `↓ New messages` button above the composer. Clicking it returns to the latest output and resumes following while preserving the draft. In a cramped terminal, the prompt may move down one row when the button appears so the transcript retains its reading position and minimum height.

Clearing context retains the transcript in its normal colors and adds a notice marking what the agent can no longer see. [App](../src/ui/app.tsx) pins that reminder above the transcript whenever its viewport without the reminder would contain rows before the latest clear. It measures that viewport first so the reminder cannot hide a row and turn itself off. The reminder leaves scrolling, selection and links tied to their displayed rows.

Observed familiar identity belongs to [CodexSession](../src/agents/codex.ts), [ClaudeSession](../src/agents/claude.ts) and [ClaudeTask](../src/agents/claude-task.ts). [Sidebar](../src/ui/sidebar.tsx) wraps identity within complete entries; [familiar projection](../src/core/familiars.ts) preserves their transcript rows when identity arrives or changes. [Background activity projection](../src/core/background-activity.ts) produces familiar and brew list updates and transcript records for Coordinator to publish and persist.

Approval previews come from the adapters; [Request](../src/ui/request.tsx), [TranscriptLayout](../src/ui/transcript-layout.ts) and [the diff renderer](../src/ui/diff.ts) own their display and full-file expansion.

Persist native IDs and display history. Each instance has one conversation open, and its coordinator exclusively owns that state. Refuse a conversation another instance holds; recover after a dead owner, stopping the agent and the shell of a Claude `!` command it left running, and reconcile native execution. Never automatically replay a prompt.

## Session coordination

GitHub assignment after an active claim belongs to [assignGitHubTask](../src/core/github-assignment.ts); [SessionCoordination](../src/core/coordination.ts) retains the local claim and returns a warning when assignment fails. The claim records each reference GitHub confirmed, and a later `--claim` assigns only its other references.

Witches sharing a state directory discover this repository's other open sessions, including its other checkouts. `/peers` shows their tasks and details without switching or messaging them. The sidebar reserves space for the usage block, then local brews and familiars, before allocating peer rows; [Sidebar](../src/ui/sidebar.tsx) owns that budget.

Observed merge delivery is owned by [SessionCoordination](../src/core/coordination.ts), the [coordination store](../src/persistence/coordination.ts), and the [event contract and projections](../src/core/merge-events.ts). [nativePrompt](../src/core/prompts.ts) supplies attributed events on eligible turns; [session state](../src/core/state.ts) owns their delivery receipts. [watchConflicts](../src/core/pr-conflicts.ts) re-reads the branch's pull request after a merge into its base and reports a conflict that `RepositoryWatch` confirmed to the transcript and to every turn until a fresh read clears it.

Peer requests let an agent ask the owner of another session's claimed task. [The request contract](../src/core/peer-requests.ts) owns projections, notices and the answer-turn and answer copy. [Coordination policy](../src/core/coordination-policy.ts) owns the ask instructions, [ConversationEvents](../src/core/conversation-events.ts) the request cache, and [SessionCoordination](../src/core/coordination.ts) admission; the [coordination store](../src/persistence/coordination.ts) owns the transactions; `Coordinator.answerPeers` and `drain` in [coordinator.ts](../src/core/coordinator.ts) own the answer turn. [nativePrompt](../src/core/prompts.ts) supplies entries that list ids, parties and claim references, and [session state](../src/core/state.ts) owns their delivery receipts. A request names a claim id and is bound to its owner, a live session in the same project whose Witch advertises support. Peer text never enters native input, since both runtimes take Witch context as user input; agents read it through the control command and transcript notices show it to the user. An answer turn only answers, and Witch refuses asks and claim changes while it runs. Each request gets at most one automatic answer attempt, never retried after interruption, failure or restart, and answers never start a turn for the asker. Queued user input, recovery, errors and pending approvals or questions come before an answer turn. An Escape or Ctrl+C that stops work holds answer turns until the user's next prompt, another conversation or `/restart`.

Agents receive fixed Witch instructions, including bound control and familiar commands, on their first native turn, after confirmed compaction and when the instruction text changes. Successful delivery is recorded per native session. Each dispatched turn still receives a fresh peer snapshot and the current selection turn ID, or an explicit indication that no selection turn is current, a line of account usage for each runtime that has a reading, and the branch's pull request conflict while one is known. After successful discovery shows no other live session, reservation or unregistered owner in the project, ordinary work needs no claim or pre-task peer query. Otherwise agents query and claim a full GitHub issue/pr URL or `task:name` before starting work, including an unclaimed task already underway. [Coordination policy](../src/core/coordination-policy.ts) owns those instructions and the current-policy statement sent with each turn. Existing claims and suggestions retain their ownership and release requirements. During an ordinary turn, a changed requirement is steered as Witch context; a refusal leaves it for the next turn. An update that enables claims covers unclaimed work already underway, and a return to solo mode explicitly supersedes earlier claim instructions. Policy updates never become queued user prompts. Matching references and explicit aliases have one owner; differently named descriptions of the same work still require the agent to recognize the overlap. Every claim lasts only while its Witch conversation stays open. Switching conversations, normal exit and process death release it; idle time, native reconnect and restart preserve it. `/task` shows this conversation's claim or selection position, and `/task release` and `/task take` show it on success from chat; `/task release` requires idle, resolved memory recovery and no running familiars or brews. `/task take <reference>` asks the owning conversation's Witch, not its model, to move that claim here; the owner applies the same gates and otherwise refuses with the user's next step. A conflicting agent claim also requests a move when the owner is idle, has no unresolved memory recovery or running familiars or brews, and reports a usage window at or above 100% whose reset is still in the future. The owner checks its current state under the ledger lock. Missing limits or reset times and error text alone do not qualify; a refused automatic request returns the conflict. Manual `/task take` does not require exhausted usage. Automatic requests stay separate from manual ones so older owners cannot treat them as user permission. The moved claim keeps its identity, references, summary and assignment, and the previous owner's turns are told it moved. An origin change leaves its existing reservation in the original project until release.

When choosing the next task, agents wait in a project queue before triage. Reserving a recommendation advances the next chooser immediately. Suggestions stay reserved until the user requests work, chooses another task or leaves the conversation; they survive native reconnect and restart. Requested work follows the promotion rules in [coordination policy](../src/core/coordination-policy.ts), including the active claim required for Copilot watching. Turn completion or interruption cancels unfinished selection, and failed cancellation retries automatically. [SessionCoordination](../src/core/coordination.ts) owns turn authority and cleanup; [CoordinationStore](../src/persistence/coordination.ts) owns FIFO order and atomic reservation transitions.

A conversation held by a current Witch does not count as unregistered, including while it opens, reconnects or closes; [StateStore](../src/persistence/store.ts) owns the locks that distinguish current and legacy owners. Restart or close older instances that appear unregistered before claiming new work. Selection also requires every live peer to support the queue. Discovery failures refuse new claims. A failed or timed-out control call grants no permission to begin work; query again to determine the outcome. Repeating a timed-out `--ask` with the same message returns the recorded request. The command uses files under the running instance's scratch directory and preserves native sandbox permissions. The task mailbox controls ownership and carries peer requests and answers; a separate familiar mailbox reports only registered native commands in the active conversation. Neither controls another session's execution or files, though a peer request can lead the recipient's own Witch to start one answer turn, an admission that Witch owns.

[Copilot review watching](../src/core/copilot-review-watch.ts) owns polling and repository/claim subscriptions. [The review controller](../src/core/copilot-review-controller.ts) owns automatic review admission, interruption and reconciliation; [feedback receipts](../src/core/copilot-reviews.ts) own disposition validation, and [review ownership](../src/core/review-ownership.ts) owns PR-to-task binding. [The GitHub reader](../src/core/github-reviews.ts) owns provider observations, [session state](../src/core/state.ts) retains receipts, and [nativePrompt](../src/core/prompts.ts) owns the agent's claim and response instructions.

## Shared memory

Keep memory in a dedicated bare Git repository, separate from logs and handoff state, and give each conversation its own worktree on its own branch. Separate global and project scopes. A project is the repository Git reaches through the origin remote, so clones share one across URL and scp forms, user names and host case. Path case still matters, and an SSH host alias counts as a host of its own. A local origin that is a repository with an origin of its own names that origin's project. A checkout without an origin, or a directory outside any repository, is a project of its own. `Workspace.begin` and `Workspace.adoptCheckout` in [workspace.ts](../src/memory/workspace.ts) own checkout-note migration and its startup recovery gates. Existing project docs remain authoritative. Agents use ordinary file tools and scoped native permissions; only the coordinator manages memory Git operations.

Each turn begins with clean memory and durable base-revision and agent metadata. Successful completion commits that turn's changes, with attribution and no empty commits. Accepted memory is `main`; a clean worktree publishes its commits by rebasing onto `main`. Interrupted, failed or uncommitted changes remain pending; block new execution until explicit accept/discard recovery. MEMORY.md, the index every agent keeps, merges both sides' lines. Any other change that conflicts with another conversation's enters conflict recovery, where keep mine resolves each conflicting change to this conversation's side and merges the rest, and discard mine resets to `main`. Never sweep another turn's pending changes into a later commit.

Before every turn, compare the accepted revision and project with those last delivered to the session, and reconnect a session granted another project's memory. Supply current essentials and changes/deletions, explicitly superseding old content. Search deeper notes as files. Memory UI supports search, history, VS Code editing while paused and restoration through a new commit. No vector store.

Snapshot delivery and memory-writing guidance belong to `Memory.snapshot` in [memory.ts](../src/memory/memory.ts) and `nativePrompt` in [prompts.ts](../src/core/prompts.ts).

## Handoffs and recovery

Stop or finish the source and resolve memory; generate and save its handoff; initialize the destination; atomically activate it. Continue only when the source's last ordinary turn was interrupted or failed. Otherwise retain the summary for the user's next prompt, treating a missing outcome as finished. [Coordinator](../src/core/coordinator.ts) owns durable ordinary outcomes and live completion signals; summaries leave the outcome unchanged, and reconnect or restart never announces an old completion. Before activation, failure retains the source. After activation, failure leaves the destination resumable. Return-to-agent resumes its prior native session unless `/clear` discarded it. Keep both sessions created since the latest clear and never replay automatically.
