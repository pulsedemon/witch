# Witch rules

## Goal and constraints

Build a full-screen terminal app for Codex and Claude Code. This is a personal macOS app with production-quality, maintainable code.

Use TypeScript, pnpm, React and Ink in one package. Use strict types, direct imports and behavioral tests. No direct provider runner, remote service, parallel task execution within a conversation, automatic Git pushes outside conflict-repair, check-repair and Copilot-feedback turns for an owned pull request, imported conversations or changes to separately launched agents. Separate instances run concurrently, each with one conversation open.

## Ownership

- UI renders coordinator state and submits typed actions. It owns focus, scrolling and hyperlink rendering, not processes or Git. The status line's Git and pull request fields come from `RepositoryWatch` in [repository.ts](../src/core/repository/repository.ts). Its pull request is the branch's own, or else one `RepositoryWatch` still follows for a branch the checkout left. `/jobs` lists and stops the process groups the agents' commands and Claude `!` commands start, including what a command leaves under launchd once its shell exits. `JobWatch` in [jobs.ts](../src/core/jobs/jobs.ts) tracks and signals them; [the CLI](../src/Witch.tsx) carries its ownership checkpoint across `/restart`. Tmux, Zellij and Emacs daemon processes, their observed descendants and any group containing them are excluded; a Witch inside them still manages its own agent commands. Emacs batch and script commands remain jobs. A marked launchd child running an executable in an app's `Contents/MacOS` in a group of its own, as LaunchServices starts the VS Code that `code` opens, or a helper from its `Contents/Frameworks`, such as its crash handler, is excluded the same way. Only the outermost app outside a framework matches. A marked orphan carrying a different macOS application's service identity stays outside jobs, including a terminal daemon that reparents between reads; the application hosting Witch does not exclude Witch's own commands. The composer's ↑/↓ prompt history reads and appends through `StateStore` in [store.ts](../src/persistence/store.ts).
- Cleanup after a pull request merges, the branch's own or one whose branch the checkout left, belongs to [watchMerges](../src/core/repository/merge-watch.ts), `cleanUpMerge` in [merged.ts](../src/core/repository/merged.ts), `refreshInstall` in [install-refresh.ts](../src/core/repository/install-refresh.ts), and `cleanUpMerge` in [coordinator.ts](../src/core/coordinator.ts), which say when and what goes. [merged-plans.ts](../src/core/repository/merged-plans.ts) owns which gitignored plans and ledgers go with a merged branch. [shared-rebuild.ts](../src/core/repository/shared-rebuild.ts) owns joining an in-flight install refresh and reporting its result. Moving a checkout never overwrites an uncommitted change or an ignored file. [instanceDirectory](../src/persistence/instance.ts) owns each instance's job-report and work-tree snapshot directories; [ScratchSpace](../src/persistence/scratch.ts) owns the agents' `TMPDIR`, its lifetime and cleanup. [Scratch usage observation](../src/persistence/scratch-usage.ts) owns the process and file evidence for cleanup.
- [Spawn](../src/cli/spawn.ts) owns the worktrees `witch --spawn` creates beside the main checkout and reuses wherever they moved, the ignored files and directories it clones into them, their pnpm installs and the Ghostty tabs it opens in them.
- Coordinator owns logical conversations, native session mappings and turn lifecycle. [SessionLink](../src/core/session-link.ts) connects and closes the native session and takes in its events; [TurnRunner](../src/core/turn-runner.ts) runs each turn. [RuntimeSwitch](../src/core/runtime-switch.ts) owns runtime switches and their durable handoffs.
- [keepAwake](../src/core/jobs/wake.ts) holds macOS's system and display idle-sleep assertions while Witch has started something that is still going: session work, merge cleanup or closing, as `witchWorking` in [coordination-state.ts](../src/core/coordination/coordination-state.ts) defines it, the automatic work [PromptDelivery.runAutomatic](../src/core/prompt-delivery.ts) flags between turns, or a job `JobWatch` tracks. Once closing begins, the hold lasts until the process exits. Waiting on the user holds nothing by itself, and neither does upkeep that starts nothing further, such as timer reads and the scratch sweep, so the system and display may idle sleep once no instance holds. Closing the lid still sleeps it.
- `SessionCoordination` in [coordination.ts](../src/core/coordination/coordination.ts) owns live session discovery, task admission and context. [Control dispatch](../src/core/coordination/control-dispatch.ts) carries out control commands, [PresencePublisher](../src/core/coordination/presence.ts) writes the session's presence, [QueuedWrites](../src/core/coordination/queued-writes.ts) owns pending peer-answer and pause writes, including retries and persistence across exit, and [TransferResponder](../src/core/coordination/task-transfer.ts) answers another conversation's request to take a claim. [The coordination store](../src/persistence/coordination.ts) owns claim, peer-request and pause transactions, and [the control transport](../src/persistence/control.ts) carries commands from native agents.
- [Preview](../src/core/preview.ts) owns transient terminal frame documents and placement for the active conversation; [Preview rendering](../src/ui/Preview.tsx) and [layout allocation](../src/ui/preview-layout.ts), divided for the chat view by [App](../src/ui/App.tsx), keep input and readable question content first. The bound control instructions own the agent-facing format and lifecycle.
- Adapters own native protocols, processes, permission requests and capabilities.
- Memory owns scoped files, accepted revisions, Git commits, publishing and interrupted-write recovery.
- Persistence owns atomic metadata, append-only display history, each directory's prompt history and conversation locks. [The directory ledger](../src/persistence/directories.ts) records known directories' identities and the moves found from them; [move repair](../src/core/repository/move-repair.ts) repairs moved conversations, and [worktree repair](../src/core/repository/worktree-repair.ts) their repositories' worktree links, at startup, before `--spawn` and for `--recover-directory`; [startup recovery](../src/core/startup-recovery.ts) reconciles abandoned conversations.

Native types stay in adapters. The steps for adding a backend are in the [README](../README.md). Keep facts in their owning source, with documentation linking to it.

## Native adapters and execution

Launch the pinned native runtimes described under [native runtime versions](#native-runtime-versions). Use Codex app-server over stdio and Claude Agent SDK with its bundled Claude Code. Preserve native prompts, instruction loading, skills, settings, hooks, integrations and permissions for user turns. Automatic peer answers use the restricted connections described under [session coordination](#session-coordination). Forward approvals, questions and MCP elicitation. Post transient notices for a Codex MCP server that fails to start and a Claude MCP server that fails to connect or needs sign-in. [ClaudeMcp](../src/agents/claude/mcp.ts) owns Claude notice timing and deduplication. Keep credentials native.

Use ordinary input for changing memory and handoffs. Do not overwrite Codex instruction configuration or rely on changed Claude system-prompt snapshots. [nativePrompt](../src/core/prompts.ts) owns instruction precedence, conflict-warning guidance and the layout of transcript replies. It also owns automatic familiar review of a plan the agent or its familiar writes, automatic follow-up auditing and issue filing after an agent opens a pull request, keeping the checkout on an open pull request's branch, fixing small flaws seen mid-task in the same change, handling bugs found mid-task in the current repository, continuing past a blocked step on the recommended route, including on another runtime when one is out of usage, and making the decisions the request, the rules or the evidence settle instead of asking. It keeps the exact user request separate from Witch context so native authorization can retain it independently. Answer turns have no user request: their context lists peer requests by id. [TurnPurpose](../src/agents/types.ts) owns the dispatch distinction. [ModelCatalog](../src/core/runtime/models.ts) combines native discovery without connecting another conversation; [Coordinator.selectModel](../src/core/coordinator.ts) owns selection, and [RuntimeSwitch](../src/core/runtime-switch.ts) the handoff. Accept explicit model IDs without silently substituting models. After a same-runtime Claude model change, the picker offers the model's 1M form when it runs below 1M. For Codex, the picker collects the model's default or maximum usable capacity before applying the model or handing off; the conversation retains its Codex choice through reconnect and, while Codex is active, `/clear` and `/new`. Reflect actual model and permission settings. Discover skills with Codex skills/list and Claude supportedCommands, and replace the list on Codex skills/changed and Claude commands_changed. Claude's built-ins are listed as native commands the composer doesn't offer, except bundled skills: built-ins in that list which the skill reload Witch requests when a native session connects also marks as built-in, until a turn's `system/init` names its own set. An init that arrives before the reload answers stops the reload, and only the init's set applies. Some bundled skills appear only in that init, so they show from the first turn. Run a skill natively: Codex gets a skill input with its path, Claude gets `/name args` as the last text block after Witch's context. Witch announces each spell cast in the transcript with a brief animation, a seeded pick among the animations for the spell's purpose, or among all of them when its name names none. It announces one the user sends, other than a Claude built-in, once the runtime takes it, and one the agent or a familiar casts through Claude's Skill tool or, on Codex, by reading a listed spell's SKILL. Connect the agent when a conversation opens, so its skills are listed before the first prompt. Witch's UI and its instructions to the agent call skills spells, subagents familiars and background commands brews. A tool row under Witch's name shows the native name when expanded.

A `!` command runs natively where it can. Codex runs it through `thread/shellCommand`, which records it in the thread. Claude Code's SDK has no such request, so Witch runs it in the user's shell, and the record goes ahead of the next prompt, modeled on Claude Code's own `!`. Either way, the prompt then goes as a turn of its own, or into a turn held open after its reply as below, and says the command already ran. A delivery hold taken while the command runs, such as an open picker or a pending `/compact`, does not stop that prompt; the hold applies from the next turn.

A prompt sent during a turn steers that turn: Claude Code folds it in at its next tool step through its own input queue, and Codex takes it through turn/steer. After its reply, [ClaudeSession](../src/agents/claude/adapter.ts) owns ordinary input admission and completion through native consumption acknowledgements and idle. A model choice is accepted during work. Claude Code takes a same-runtime change during an ordinary turn at its next model request. Other choices wait for the operation and any background work their reload or handoff would discard. `Pending: /model …` stays visible while the choice waits, and the selection finishes before the next queued turn. A stop after the choice or a failed operation cancels it with a notice; a choice made after a stop waits for that stop to settle. The picker opened during an operation shows the models already listed; at idle it refreshes them. While a background familiar or workflow holds a replied turn open, Witch runs a `!` command at once and steers its reply in once it completes. Until then the turn stays open and takes no other prompt; model changes wait for the operation. Witch runs its own commands itself. Any other prompt that starts with `/` is a command only when its first word names a listed spell or native command; any other, such as a path, steers as a prompt, and Claude gets it as written. A spell or native command sent during a turn goes to the runtime once it can take it: Claude runs it after the current native turn within the same turn, and without message lifecycle only once the turn has replied. One the runtime refuses, as Codex does since it runs a spell only at a turn's start, waits in Witch's queue for a turn of its own without holding the prompts sent after it. Any other prompt the turn can't take waits in Witch's queue for a later turn: one the turn refuses, one sent behind a queued ordinary prompt or `!` command, one sent after an interrupt, or a `!` command outside the supported window. Queued, a spell, native command or `!` command never joins other prompts' text: at the queue's head it goes alone, and the prompts before the next one go as one turn, a line each. With no session connected, any prompt that starts with `/` goes alone. Once a queued turn's prompt is sent, the prompts queued behind it steer into that turn; the prompts queued behind a `!` command wait for a turn after it. Witch's other commands that act on the conversation, such as `/new` and `/clear`, still need idle. In that window, outside a `!` command, their refusal says to wait for the running familiars or workflows, or press Escape. A switch to another conversation is refused while prompts are queued and takes none until the next one opens. An interrupt leaves the queue to run next, along with the prompts Claude Code reports it never read, except one that stops Witch continuing on another runtime after usage exhaustion. Unread records of completed Claude `!` commands stay with their conversation until its next dispatched prompt, even across a native reconnect or conversation switch, unless `/clear` discards them. They go as context without queuing another turn or rerunning the commands, and remain only for the current Witch process. A queued turn that never reaches the agent keeps its prompts queued, a report or a failed turn keeps the rest queued so it stays on screen, and the composer takes them back. After a turn that runs out of usage, the queue runs on the runtime Witch continues on, and a blocked or interrupted switch returns it to the composer. A prompt sent while Witch continues there queues rather than steering. Invalid `/task` arguments, failed `/task release` and `/task take`, Witch commands refused because another operation is running, model and spell discovery failures, failed link resolution, and failed desktop open or clipboard commands post transient notices and leave queued prompts runnable. A prompt sent during a Witch-started answer, repair or Copilot-review turn queues and runs after it, or returns to the composer if that turn fails. Commands that need idle are refused during these turns, and Escape stops them.

Claude completion follows native idle once the connection has reported session state. A prompt sent while Claude Code runs on its own opens a turn that Claude Code takes into that run at its next tool step; the turn completes on the result naming its input, never on the run's own result, which names none. Without any session-state event, [ClaudeSession](../src/agents/claude/adapter.ts) completes on a result after tracked native familiars, workflows, accepted input and held command replies settle, and posts a notice that idle tracking is missing.

Explicit interruption and closure share a deadline through [Coordinator](../src/core/coordinator.ts) and the adapters. [Shutdown](../src/agents/shutdown.ts) owns the budget and targeted process escalation. Codex restart retains its existing teardown policy. Normal turns and background work have no deadline.

`/clear` requires idle and no queued prompts, as `/new` does. [SessionLink.clear](../src/core/session-link.ts) starts a fresh native session inside the same conversation, retaining its claim, scratch, memory workspace, model and effort. A refusal fallback ends with that native session; the model before it returns unless the user has since selected a model. It discards both runtimes' saved context, pending handoff and unread command output, and the old ordinary-turn outcome. The next turn receives shared memory and Witch's instructions again.

### Witch commands and compaction

[The command catalog and parser](../src/ui/commands/commands.ts) own names, aliases and arguments. A message that starts with a Witch command runs every whitespace-delimited Witch command outside backticks, in order. In a message that starts otherwise, `/new`, `/clear`, `/restart` and `/exit` (or `/quit`) stay text and other Witch commands still run; with none left, the message goes to the agent unchanged. A leading `!` or listed native command preserves the whole input; a leading Witch command takes precedence over a native name collision. Unknown slash words and paths remain ordinary input. Backticks protect literal command names, including an unclosed span through the end of the message. Commands marked `takesArguments` in the catalog consume arguments up to the next Witch command. Other commands take none. Surrounding prose is discarded, the original message stays in prompt history, and none of it reaches the agent.

[Command batches](../src/ui/commands/command-batches.ts) await operations, picker selection or dismissal, nested effort choices and model application, including a choice waiting for running work. They hold prompt delivery across the entire sequence, including separately submitted batches waiting behind it. Failure, refusal or interruption cancels the remaining commands across all accepted batches; a notice lists exact commands and arguments for explicit retry. Completed commands are omitted. Canceled command text never enters the composer. Escape dismisses a picker successfully; Ctrl+P replaces it as a dismissal. Exit and restart discard the remaining sequence. Other commands retain their existing busy-conversation refusal rules.

`/compact` is accepted during work. Codex waits for the active turn to finish because its native manual compaction interrupts that turn. Claude waits for foreground native execution, then compacts while background familiars or workflows can remain active. [ClaudeCompaction](../src/agents/claude/compaction.ts) requires a matching result and confirmed manual history replacement without finishing the ordinary turn. `Pending: /compact` remains visible until the request completes. Concurrent API callers share a request; repeated explicit commands run separately. A manual request joins automatic compaction already in progress.

[Compaction requests](../src/core/compaction.ts) are scoped to their conversation and operation. [PromptDelivery](../src/core/prompt-delivery.ts) blocks both direct steering and queued delivery from admission until compaction completes, then retains any command-batch hold. Failure, cancellation, recovery or a conversation change stops the request and leaves later prompts undelivered. A failed busy compaction keeps the parent activity's hook writes pending for recovery even if its ordinary result succeeds; a successful one does not commit while the parent remains active. [Memory settlement](../src/core/memory-settlement.ts) classifies unpublished writes and conflicts after the owning operation ends.

Queued input returns to the composer only after command-batch and compaction holds clear and only when the existing draft and proposed merged text would not execute Witch commands. Unsafe merges retain both the draft and original queue entries. Automatic recovery retries when the draft becomes empty; Up-arrow or another queue/phase transition can recover a nonempty safe draft. With an unsafe queue-only merge, a new ordinary submission resumes the original message boundaries. Fatal errors retain unconditional recovery for copying from the disabled composer.

Automatic compaction uses [the shared policy](../src/core/compaction-policy.ts) before every turn `drain` starts and inside owned native conversation sessions. Unknown capacity retains the pre-turn percentage rule without inventing a native token target. [Codex's policy](../src/agents/codex/compaction-policy.ts) derives capacity from the native catalog and configures start/resume; a model change requiring a different limit waits while background work would be lost by a reload; the adapter also refuses an unsafe direct selection. [Claude's context handler](../src/agents/claude/context.ts) applies a session-only percentage without changing the displayed window. Native safety limits can compact earlier. Isolated peer-answer sessions retain native compaction settings.

Native sessions, settings, hooks and Witch's transcript persist across compaction. Confirmed replacement invalidates delivered context; [nativePrompt](../src/core/prompts.ts) supplies accepted memory and Witch instructions at the next dispatched turn. During a turn, Claude's compact-resume hook restores the full context before native inference continues, even though its replacement notification follows the hook. When no hook restores context, including when native settings disable hooks, Witch sends a context-only steer, after manual compaction when steering was refused until then. Neither restoration marks that context delivered for the next turn.

`/review <files>` runs review rounds over working-tree files in the conversation's directory as one operation; [runReview](../src/core/review/review-run.ts) owns the loop and [review.ts](../src/core/review/review.ts) its round decisions. The mechanical checks and reviewers read each round's checked target snapshot. Before routing reviewers, [mechanical checks](../src/core/review/review-checks.ts) run on markdown targets, and a correction turn fixes failures no correction has received, with one more turn for any it introduced. Witch routes the round with `--route review`, launches each reviewer's familiar wrapper itself, read-only and lean, without MCP servers or the spell catalog, through [Reviewers](../src/core/review/reviewers.ts), which the familiar mailbox asks before the live session, and waits for every reviewer to exit. A reviewer whose familiar doesn't complete on its routed model with exit code 0, or whose report's last json block doesn't parse as findings on the targets, stops the review. One silent correction turn then gets every finding: blockers to apply, non-blocking findings to fix when small or track as issues. Round 1 and the closing pass review the full text; other rounds review the diff since the last round unless it changed more than half the text. A runtime whose reviewers found no blockers sits out the next round, every runtime returns after a round that ran without one and changed the text, a quiet diff round leads to a closing full pass, and a quiet full round settles the review. The review also stops once every blocker sits on lines corrected since the last round's reviewers read the text, mechanical corrections included, after correcting them. Memory publishes after each correction turn, and any failure, refusal or interruption stops the review, cancels the rest of the command batch, and stops every reviewer by the shared stop deadline. The conversation shows `/review <files>` once, then a notice per round naming its reviewers, their models and who sits out, and a finish notice; the agent's next turn gets the outcome as context.

Codex commands that outlive their originating native turn become brews through [CodexSession](../src/agents/codex/adapter.ts); later turns leave them visible until completion. [SessionLink](../src/core/session-link.ts) keeps unfinished tool output on its original transcript row throughout that native connection.

Agents delegate work only through Witch's familiar wrappers, on either runtime and from either one, never their own subagent tools, since only the wrapper's model argument guarantees the model that runs. This is general-purpose delegation, including implementation, investigation and review. Before each, the agent asks `--route`, and Witch launches the reviewers of `/review` itself; [routing.ts](../src/core/runtime/routing.ts) owns the choice of runtime and model from the user's `/delegation` policy, the producer of work under review and each runtime's usage, resolving a family to its newest model and running a versioned model as named. `--tier` takes each runtime's family at that tier from the tier table, keeping the policy family when it is one of them, falls back to the policy family with the reason in the route, and leaves a pinned rule's model alone. A review with no rule goes to every installed runtime, and the agent launches a familiar on each route. Unconfigured planning, implementation and investigation use automatic placement. [Capacity](../src/core/runtime/capacity.ts) owns the ranking of remaining allowance against reset timing and observed work, coordinator protection under quota pressure, and destination eligibility. [Demand](../src/core/runtime/demand.ts) counts activity across projects from verified live sessions, retaining uncertainty for open owners without verified presence and older sessions without familiar runtime counts. The requesting session uses its current state before a coalesced presence write. Running familiars count on the runtime they use. Simultaneous route requests can make the same choice before those familiars register; routing reserves no future jobs. [Account usage](../src/core/runtime/usage.ts) owns selected-model windows, freshness and verified credit capacity; a destination's credits count only at 100%, while usable credits preserve its own high-usage placement. A confirmed usage refusal, from the conversation's own turn or a familiar's, marks the runtime out of usage until the refused window's reset time passes or a later reading shows included room, unlimited credits, or a credit balance above the lowest seen since. A refusal whose limit names a model label blocks only the models that label names; one that names none blocks the whole runtime, and its credits don't count anywhere. Meanwhile routing that names no model neither returns a blocked model nor shifts work to it, and a review whose share has nowhere to go leaves that runtime out rather than refusing the other runtime too. The [delegation page](../src/ui/commands/delegation.ts) describes the current policy and its overrides. [Router](../src/core/runtime/router.ts) answers the request and records each choice and its reason in the transcript, in the warning color when capacity moved the work, with its own line for a runtime a review passed over or left out. The Claude wrapper passes its own settings so a legacy remap or fallback can't replace that model. It also appends an instruction to repeat the complete answer in a turn a background notification starts after it, since an ordinary Claude familiar saves its latest successful nonempty result and native output cannot distinguish an acknowledgement from an answer. [The Claude wrapper](../src/cli/cli-familiar.ts) and [Codex wrapper](../src/cli/cli-codex-familiar.ts) use the bound invocations supplied by [nativePrompt](../src/core/prompts.ts). Native commands retain execution, permission and job ownership. [CodexCommands](../src/agents/codex/commands.ts) and [ClaudeCommands](../src/agents/claude/commands.ts) own task association and lifecycle. [ClaudeTask](../src/agents/claude/task.ts) translates Claude's stream; the Codex wrapper reuses [CodexAdapter](../src/agents/codex/adapter.ts) and forwards its native requests through Witch. A native result alone does not establish process cleanup. The ordinary wrappers save a completed familiar's final answer, or a failed or stopped one's full report, to a new task-scratch file, and print the full report with progress messages and diagnostics. This reporting path does not survive `/restart`. The Codex wrapper fails a familiar that hasn't sent its turn within `startupDeadlineMs` of registering and names the step it waited for; a running turn has no deadline.

Agent-initiated plan review uses the same native launch and routing path. [The plan-review preset](../src/cli/plan-review.ts) reads the draft and brief after Witch admits the familiar, using the session directory and scratch directory returned by the host. Each input must be a regular UTF-8 file of at most 2 MiB. Witch publishes a completed review after the carrying command exits successfully. The result records the terminal status, the draft digest and reported model when available, and validated findings or the failure reason. The caller checks the exit code and compares the receipt with the draft it uses. [The startup instructions](../src/core/prompts.ts) own the caller's coverage and digest checks.

### Claude command routing

[textCommands](../src/agents/claude/spells.ts) owns the commands sent as text because they overlap Witch's history, displayed settings, conversation titles or compaction policy. Unlisted slash prompts go as text on both initial and steered input, even without a context prefix.

The state-changing commands audited against the [pinned native version](../package.json) use these routes:

| Command           | Route                 | Native effect and ownership                                                                                                                                                                                  |
| ----------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `autocompact`     | Native                | Changes the per-model compaction window in user settings; it cannot turn compaction off. Witch's compaction policy still applies.                                                                            |
| `config`          | Text                  | Can disable native auto-compaction and change model settings outside Witch's selection flow.                                                                                                                 |
| `output-style`    | Native                | Selects a native output style and saves it in project-local Claude settings. Claude owns its prompt styles.                                                                                                  |
| `rename`          | Text                  | Changes Claude's session name without changing Witch's conversation title.                                                                                                                                   |
| `advisor`         | Native when available | Configures a separate native advisor, preserving the main model. Saves the advisor choice in native user settings.                                                                                           |
| `auto-mode-setup` | Native                | Proposes and applies Claude's auto-mode environment and classifier rules. Applying a reviewed proposal requires its exact file hash and writes native user settings, including for project-scoped proposals. |

## Native runtime versions

Witch runs the Claude Code bundled with its pinned `@anthropic-ai/claude-agent-sdk` and the pinned `@openai/codex`, never the `PATH` installs, and does not change the user's native installations. [nativeExecutable](../src/agents/executable.ts) names each binary through pnpm's package link, so every launch reaches the version installed at that moment, and [nativeLaunch](../src/agents/native-launch.ts) starts its real path. A Dependabot pull request moves the pins; the schema guard, typecheck, the replays and `pnpm native:check` check it, as the [README](../README.md#native-protocol-fixtures) describes.

Open sessions take a bump through `/restart`. Until then, a session can launch the new binary with its old code, and a native process started before the merge can lose bundled tools once pnpm prunes the old version. [Native verification](../src/agents/native-check/native-verification.ts) owns the live check's profile and evidence, including old-version conversation recall through the candidate, ordinary settings, permission boundaries and native lifecycle checks. User sessions, hooks and connected tools are excluded from synthetic checks.

## Terminal UI and persistence

Task titles, attention eligibility and pending-alert cancellation belong to [watchTerminal](../src/ui/terminal/terminal.ts), which observes coordinator and session-coordination state. [NotificationSchedule](../src/persistence/notifications.ts) owns desktop spacing and its persisted record. [TurnRunner](../src/core/turn-runner.ts) supplies successful completion of normal turns, which an answer turn doesn't delay; [the CLI](../src/Witch.tsx) provides the schedule, cancels attention before teardown and resets the title during final terminal restoration.

Use an alternate screen with a phase row at the top, a scrolling transcript, a multiline composer that grows with its text up to half the rows the phase row, errors and status line leave, and a status line at the foot, normally two rows, rendered by [StatusLine](../src/ui/status/StatusLine.tsx) for either agent, with `~/.claude/statusline.sh` as its baseline. The phase row shows the phase, except that an idle session reads `RUNNING` while its native agent runs on its own and `BACKGROUND` while its familiars or brews run, per [sessionStatus](../src/core/coordination/coordination-state.ts). Without the sidebar, it also counts the running familiars and brews. Render at every terminal size and keep input available. Reserve the active input and transcript before secondary rows, reducing borders, padding, hints, the tool window and footer as space runs out. Resizing retains the current view, draft, selected options and reading position. Approval and question controls stay within the available body height. In the chat view, a four-row window, reduced when the terminal cannot fit it, above the working row and composer shows the latest three agent tool titles with running, finished or failed markers, plus a heading counting running calls and any older running calls outside the window. Completed calls remain until newer calls replace them, including between turns. Familiar and brew activity stays in the sidebar, user `!` commands stay in the transcript, and tool output still requires expansion. The window never changes size with tool activity or changes the transcript reading position. While a Witch turn works, a row above the composer says so and counts the time since it began, and queued prompts show above the command window; a native run outside a turn gets no such row, since Escape can't stop it. During native Codex compaction in the `running` phase, the working row starts with `COMPACTING` until that compaction finishes or stops, retaining its operation timer. In the `running` phase that row also reports on the agent's current rows, the text and tool rows [agentActivity](../src/ui/status/agent-activity.ts) selects: after `QUIET`, the time since one of them last changed, or since the count began while there are none, and after `RUNNING`, the newest unfinished tool call among them. Between those two, after `THOUGHT`, it shows how long ago the agent itself last reported reasoning, while that is later than the time `QUIET` counts from; an adapter reports that reasoning happened and never its text. `QUIET` keeps counting while `/review` waits on its reviewers. ## Session coordination

GitHub assignment after an active claim belongs to [assignGitHubTask](../src/core/coordination/github-assignment.ts); [control dispatch](../src/core/coordination/control-dispatch.ts) retains the local claim and returns a warning when assignment fails. The claim records each reference GitHub confirmed, and a later `--claim` assigns only its other references.

Witches sharing a state directory discover this repository's other open sessions, including its other checkouts. `/peers` shows their tasks and details without switching or messaging them. The sidebar reserves space for the usage block, then local brews and familiars, before allocating peer rows; [Sidebar](../src/ui/status/Sidebar.tsx) owns that budget.

Observed merge delivery is owned by [SessionCoordination](../src/core/coordination/coordination.ts), the [coordination store](../src/persistence/coordination.ts), and the [event contract and projections](../src/core/repository/merge-events.ts). [nativePrompt](../src/core/prompts.ts) supplies attributed events on eligible turns; [session state](../src/core/state.ts) owns their delivery receipts. [watchConflicts](../src/core/repository/pr-repair.ts) re-reads the branch's pull request after a merge into its base and reports a conflict that `RepositoryWatch` confirmed to the transcript and to turn context (below) until GitHub reports the pull request mergeable or it closes; an uncomputed read keeps it, even at a pushed head or a new base. When this session's claim references that pull request, [PullRequestRepair](../src/core/repository/pr-repair.ts) requests a fresh read before admission and starts one Witch-started turn only if it still conflicts at the current local head. That turn merges the base without rebasing, verifies and pushes. The repository watch also refreshes the pull request after an observed head or upstream-status change, so a confirmed resolution clears active conflict state without waiting for the normal poll. When the latest read instead shows a failed check, GitHub's latest run of that check, PullRequestRepair starts one turn that finds the cause and fixes it, or matches a failure outside the change to an issue before rerunning the job. Either repair runs after queued user turns and peer answers and before Copilot reviews, checks ownership when admitted, again before native input and throughout the turn, and is held after a stop like other automatic turns. Each conflicting head and base, and each failed check on a head, is attempted once, including across `/restart`; a failed ownership check declines it with a notice until the user's next prompt or another conversation.

Peer requests let an agent ask the owner of another session's claimed task. [The request contract](../src/core/coordination/peer-requests.ts) owns projections, notices and the answer-turn and answer copy. [Coordination policy](../src/core/coordination/coordination-policy.ts) owns the ask instructions, [ConversationEvents](../src/core/coordination/conversation-events.ts) the request cache, and [SessionCoordination](../src/core/coordination/coordination.ts) admission; the [coordination store](../src/persistence/coordination.ts) owns the transactions; [PromptDelivery](../src/core/prompt-delivery.ts) admits the answer turn, and [TurnRunner](../src/core/turn-runner.ts) runs it. [nativePrompt](../src/core/prompts.ts) supplies entries that list ids, parties and claim references, and [session state](../src/core/state.ts) owns their delivery receipts. A request names a claim id and is bound to its owner, a live session in the same project whose Witch advertises support. Peer text never enters native input, since both runtimes take Witch context as user input. Automatic answers read a private request file; ordinary turns can read requests through the control command. Transcript notices show requests and recorded answers to the user. [Peer answers](../src/core/coordination/peer-answers.ts) owns the strict response contract and validates the complete batch before the coordination store records it atomically, preserving replies already recorded during the turn. Invalid or incomplete responses publish no answers. A completed answer whose write runs out of time waiting for the ledger stays queued in `QueuedWrites`, which `SessionCoordination` flushes on each tick and once at deactivation; the turn is not rerun. Writes still queued when Witch closes are saved in the coordination directory, and the next Witch to start records them. A queued write that fails for another reason while Witch closes fails the close with that error. An answer turn only answers, and Witch refuses asks and claim changes while it runs. Each request gets at most one automatic answer attempt, never retried after interruption, failure or restart, and answers never start a turn for the asker. Queued user input, recovery, errors and pending approvals or questions come before an answer turn. An Escape or Ctrl+C that stops work holds answer, repair and Copilot review turns until the user's next prompt, another conversation or `/restart`.

Automatic answers run in a separate restricted native process with the owner's history when available. [AnswerTurn](../src/agents/answer-turn.ts) owns that connection and its shutdown; the normal owner session remains open with unchanged permissions. The Codex adapter uses an ephemeral thread with no approvals, local writes, network, connected tools or delegated work; [answer configuration](../src/agents/codex/answer.ts) preserves configured read boundaries, adds read access to the exact request file and disables hooks. The Claude adapter exposes only read tools and structured output, with hooks and MCP disabled. Startup recovery stops a leftover answer process using the same identity checks as the normal native process. Answers never consume the normal session's memory or context delivery receipts.

An agent pauses other sessions with `--pause` when its user asks. [ConversationPauses](../src/core/coordination/conversation-pauses.ts) owns recipient execution. [The pause contract](../src/core/coordination/pauses.ts) owns the record, recipient selection, statuses and recipient notices; [coordination policy](../src/core/coordination/coordination-policy.ts) owns the agent instructions, [control dispatch](../src/core/coordination/control-dispatch.ts) admission and the coordination store the transactions. Recipients are fixed when the pause is recorded: every other live session in the issuer's project, or only the live sessions named with `--to`, in any project. Every recipient must advertise pause support, and an unregistered session in the issuer's project refuses a default pause, so a pause is never recorded for fewer sessions than asked. A session opened later is never a recipient. A retried `--pause` from the same turn with the same `--to` list returns the recorded pause. Each recipient's Witch holds queued prompts and automatic turns, stops its work as Escape does, retrying a failed stop, and records a confirmation once the stopped operation has settled and any native run outside a turn, which Escape can't stop, has ended; `--pause-status` reports a recipient `pending` until then, `paused` after and `resumed` once lifted. A pause that arrives while an operation the user started is running stops it before confirming, and automatic turns wait until the open conversation's pauses have been read. The issuer's `--resume` lifts every remaining recipient and leaves a user's own Escape hold in place; the user's next prompt in a paused conversation lifts that conversation only, including pauses issued before it that this Witch had not read yet, and runs ahead of the automatic work the release wakes. A pause survives switching conversations and `/restart`, unlike an Escape hold. The recipient's confirmation and resume writes go through [QueuedWrites](../src/core/coordination/queued-writes.ts) too: `SessionCoordination` retries them on its tick, flushes them before the conversation closes and keeps the rest across exit like a queued answer.

Agents receive fixed Witch instructions, including bound control and familiar commands, on their first native turn, after confirmed compaction and when the instruction text changes. Successful delivery is recorded per native session. Each dispatched turn still receives a fresh peer snapshot and the current selection turn ID, or an explicit indication that no selection turn is current, a line of account usage for each runtime that has a reading, and the branch's pull request conflict while one is known, except a conflict-repair turn, whose instruction carries it. [Coordination policy](../src/core/coordination/coordination-policy.ts) owns those instructions and the current-policy statement sent with each turn. Existing claims and suggestions retain their ownership and release requirements. During an ordinary turn, a changed requirement is steered as Witch context; a refusal leaves it for the next turn. A session retains a pull request claim while its authorized work continues, including automatic feedback handling and maintenance through integration. ## Shared memory

Keep memory in a dedicated bare Git repository, separate from logs and handoff state, and give each conversation its own worktree on its own branch. Separate global and project scopes. A project is the repository Git reaches through the origin remote, so clones share one across URL and scp forms, user names and host case. Path case still matters, and an SSH host alias counts as a host of its own. A local origin that is a repository with an origin of its own names that origin's project. A checkout without an origin, or a directory outside any repository, is a project of its own. `Workspace.begin` and `Workspace.adoptCheckout` in [workspace.ts](../src/memory/workspace.ts) own checkout-note migration, taking a path-keyed project's notes along when its directory moves, repointing notes at directories that moved, and their startup recovery gates. Existing project docs remain authoritative. Agents use ordinary file tools and scoped native permissions; only the coordinator manages memory Git operations.

Each turn begins with clean memory and durable base-revision and agent metadata. Successful completion commits that turn's changes, with attribution and no empty commits. Accepted memory is `main`; a clean worktree publishes its commits by rebasing onto `main`. Interrupted, failed or uncommitted changes remain pending; block new execution until explicit accept/discard recovery. MEMORY.md, the index every agent keeps, merges both sides' lines. Any other change that conflicts with another conversation's enters conflict recovery, where keep mine resolves each conflicting change to this conversation's side and merges the rest, and discard mine resets to `main`. Never sweep another turn's pending changes into a later commit.

Before every turn, compare the accepted revision and project with those last delivered to the session, and reconnect a session granted another project's memory. Supply current essentials and changes/deletions, explicitly superseding old content. Search deeper notes as files. Memory UI supports search, history, VS Code editing while paused and restoration through a new commit. No vector store.

Snapshot delivery and memory-writing guidance belong to `Memory.snapshot` in [memory.ts](../src/memory/memory.ts) and `nativePrompt` in [prompts.ts](../src/core/prompts.ts).

## Handoffs and recovery

Stop or finish the source and resolve memory; generate and save its handoff; initialize the destination; atomically activate it. Continue when the source's last ordinary turn was interrupted or failed, or a confirmed background exhaustion left its task unfinished. Otherwise retain the summary for the user's next prompt, treating a missing outcome as finished. [TurnRunner](../src/core/turn-runner.ts) owns durable ordinary outcomes and live completion signals; summaries leave the outcome unchanged, and reconnect or restart never announces an old completion. Before activation, a failed source summary is replaced by context Witch rebuilds from the transcript, leaving out prompts the agent never read, which the queue sends again, while cancellation, a pending memory decision and destination failure retain the source. After activation, failure leaves the destination resumable. Return-to-agent resumes its prior native session unless `/clear` discarded it. Keep both sessions created since the latest clear and never replay automatically.

When an ordinary turn, the compaction Witch runs before delivering it, or a native background continuation of ordinary work fails on a confirmed native usage-exhaustion signal, [RuntimeSwitch](../src/core/runtime-switch.ts) continues the conversation on another installed runtime with current headroom or verified credit capacity, without asking the exhausted source for a summary. A prompt that compaction held back stays queued for the destination, after any continuation the source's last ordinary turn calls for. Each adapter owns its signal; error text, a plain rate limit or a full meter alone never confirms one. A background failure waits for native idle and current settlement, without dispatching queued input to the exhausted source. Background failures preserve the completed ordinary outcome, carry completed tool reports into fallback context, and protect uncommitted memory from automatic acceptance. A pending memory decision comes first, and resolving it rechecks the switch admission gates. Pending Witch commands make it yield, and a pending compaction runs on the destination after the continuation. The transcript names the switch and its reason, or the blocker when no runtime qualifies. The switch notice names the limit that ran out, its reset and why credits could not cover it, as far as the runtime reported them. A continuation that also runs out ends with a blocker instead of switching back. Witch doesn't switch on open, so a restart before activation or during the memory decision leaves the source until the next exhausted prompt.
